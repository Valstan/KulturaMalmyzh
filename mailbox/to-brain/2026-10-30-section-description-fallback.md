# Описание разделов ДК: кодовый фолбэк

**Вопрос снят.** Мы писали: метатег `description` есть на `/`, `/news`, `/dk`,
`/faq`, `/prazdniki`, `/privacy` и его нет на `/dk/rckd` и `/dk/kalinino`, потому
что поле `institutions.description` в карточках пустое — это данные, а не код.
Было два пути: наполнять руками в админке (как адреса и телефоны) или кодовый
фолбэк. **Решение владельца 30.10 — кодовый фолбэк.** Сделали: PR #167 влит
30.10, деплой на прод зелёный.

**Как устроено.** Текст собирается из фактов, которые уже есть в карточке, плюс
известное свойство портала. Ничего за учреждения не сочиняем — код лишь
подставляет подпись из того, что владелец уже заполнил:

- **живое описание всегда выигрывает** — заполнил админку, значит в метаданные
  попало как есть, без склейки; фолбэк включается только когда поле пустое;
- иначе — название и населённый пункт: «Дом культуры села Калинино» + «с.
  Калинино» → «Дом культуры села Калинино: новости и афиша на портале «Культура
  Малмыжского района».»;
- населённый пункт не дублируется, если название его уже называет (см. Калинино
  выше); «Малмыжский» ≠ «Малмыж», поэтому у РЦКД поселение остаётся;
- без названия фолбэка нет — придумывать имя учреждения нельзя;
- подпись под заголовком страницы (hero) осталась **только живой**: автоматическая
  строка под названием видна человеку и была бы шумом. Фолбэк живёт в
  метаданных.

**Приёмка — по факту, с прода (после деплоя):**

| раздел | `meta description` |
|---|---|
| `/dk/rckd` | Малмыжский районный Центр культуры и досуга — г. Малмыж: новости и афиша на портале «Культура Малмыжского района». |
| `/dk/kalinino` | Дом культуры села Калинино: новости и афиша на портале «Культура Малмыжского района». |
| `/dk/adzhim` | Аджимский сельский Дом культуры — с. Аджим: новости и афиша на портале «Культура Малмыжского района». |
| `/dk/savali` | Дом культуры села Савали: новости и афиша на портале «Культура Малмыжского района». |

- `og:description` на разделах — тот же текст;
- разметка JSON-LD раздела несёт то же описание (было — без него);
- остальные страницы не сломались: 8 публичных страниц — HTTP 200, маркер
  «Малмыж» на месте, прежние описания не тронуты;
- в гейтах PR #167 зелёное: юнит-тесты 355/355 (9 новых), lint 0, typecheck 0.

**Что это не значит.** Описаний за учреждения мы не написали — это подпись из
фактов, одинаковая по форме у всех разделов. Как только владелец напишет
описания в админке, они заменят фолбэк без правки кода (в админке у поля
добавлена подсказка: пусто — подставится текст из названия и населённого
пункта).

**Что дальше.** Ваш пункт по `description` закрыт: решение принято, код влит,
прод проверен. Остальные открытые пункты без изменений.
